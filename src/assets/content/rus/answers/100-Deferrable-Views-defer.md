<h3>Что это такое?</h3>

<p><span class="accent">Deferrable Views</span> — это механизм, который позволяет отложить загрузку части шаблона (вместе со всеми дочерними компонентами, директивами и пайпами) до тех пор, пока не выполнится определенное условие.</p>

<p>При сборке приложения Angular автоматически выделит код внутри блока <code>@defer</code> в отдельный JavaScript-чанк (chunk). Этот чанк будет загружен по сети только тогда, когда сработает триггер.</p>

<h3>Как это выглядит в коде?</h3>

<p>Синтаксис основан на новых блоках управления потоком (Control Flow):</p>

<code class="code">
  @defer (on viewport) {
    &lt;!-- Этот компонент загрузится только когда блок появится на экране -->
    &lt;app-heavy-chart [data]="chartData">&lt;/app-heavy-chart>
  } @placeholder (minimum 500ms) {
    &lt;!-- Показывается до того, как сработает триггер загрузки -->
    &lt;!-- 500 мс это минимальное время отображения плейсхолдера -->
    &lt;div class="skeleton-loader">Скролльте вниз...&lt;/div>
  } @loading (minimum 1s; after 200ms) {
    &lt;!-- Показывается во время скачивания JS-чанка по сети -->
    &lt;!-- минимальное время отображения 1 секунда, задержка перед показом 200 мс -->
    &lt;app-spinner>&lt;/app-spinner>
  } @error {
    &lt;!-- Показывается, если сеть отвалилась или чанк не скачался -->
    &lt;div class="error">Не удалось загрузить график :(&lt;/div>
  }
</code>

<h3>Основные блоки структуры</h3>
<p>Для управления UX во время этого процесса есть четыре секции:</p>

<p>1.<code>@defer</code> — сам контент, который нужно загрузить лениво.</p>

<p>2.<code>@placeholder</code> — то, что видит пользователь до срабатывания триггера.</p>

<p>3.<code>@loading</code> — то, что видит пользователь во время загрузки чанка по сети.</p>

<p>4.<code>@error</code> — то, что покажется, если сеть отвалилась и чанк загрузить не удалось.</p>

<h3>Триггеры: как мы управляем загрузкой</h3>

<p>
  Angular предоставляет богатый набор встроенных триггеров. Их можно комбинировать (например, <code>on viewport, timer(5s)</code>).
</p>

<table>
  <tr>
    <th>Триггер</th>
    <th>Описание</th>
  </tr>
  <tr>
    <td>on idle (По умолчанию)</td>
    <td>Загружает чанк, когда браузер освобождается от основных задач (использует requestIdleCallback). Идеально для некритичного UI.</td>
  </tr>
  <tr>
    <td>on viewport</td>
    <td>Загружает контент, когда блок <code>@placeholder</code> (или указанный элемент) попадает в видимую область экрана. Заменяет сторонние библиотеки вроде Intersection Observer.</td>
  </tr>
  <tr>
    <td>on interaction</td>
    <td>Загружает контент при клике или фокусе на <code>@placeholder</code> (или другом элементе).</td>
  </tr>
  <tr>
    <td>on hover</td>
    <td>Скачивает чанк при наведении мыши.</td>
  </tr>
  <tr>
    <td>on immediate</td>
    <td>Начинает загрузку сразу же, без ожидания.</td>
  </tr>
  <tr>
    <td>on timer(X)</td>
    <td>Загружает компонент через заданное время (например, on <code>timer(2s)</code>).</td>
  </tr>
  <tr>
    <td>when &lt;условие&gt;</td>
    <td>Пользовательский триггер на основе <code>boolean</code> переменной (например, when <code>isMenuOpen</code>).</td>
  </tr>
</table>

<h3>Prefetching (Предзагрузка)</h3>
<p>Позволяет начать загрузку чанка заранее, до срабатывания триггера. Например, <code>@defer (on timer(5s); prefetch)</code> начнет загрузку через 5 секунд после рендера, даже если пользователь еще не достиг нужного места на странице.</p>

<p>Это полезно для контента - можно скачать контент заранее, а открыть его только при определенном условии (например, когда пользователь прокрутит страницу до нужного места или при клике). Это улучшает пользовательский опыт, снижая время ожидания.</p>

<code class="code">
  @defer (on interaction; prefetch on idle) {
    &lt;app-complex-dialog>&lt;/app-complex-dialog>
  } @placeholder {
    &lt;button>Открыть сложный диалог&lt;/button>
  }>
</code>

<h3>Как это работает под капотом</h3>
<p><strong>Анализ компилятора:</strong> Angular Compiler (Ivy) находит блок <code>@defer</code> и анализирует все зависимости внутри него (компоненты, директивы, пайпы).</p>

<p><strong>Генерация чанков:</strong> Зависимости, которые не используются вне блока <code>@defer</code>, выносятся в отдельный файл (например, chunk-XYZ.js).</p>

<p><strong>Выполнение в рантайме:</strong> На этапе выполнения Angular рендерит только <code>@placeholder</code>. Когда срабатывает триггер (например, Intersection Observer для <code>on viewport</code>), Angular делает <code>import()</code> для сгенерированного чанка.</p>

<p><strong>Рендеринг:</strong> После загрузки Angular убирает <code>@placeholder</code> / <code>@loading</code> и рендерит содержимое <code>@defer</code>.</p>
