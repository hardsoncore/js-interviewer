<p class="info info--blue">
  В современной разработке прототипное наследование часто спрятано под капотом классов или абстракций фреймворков, четкое понимание этой механики — отличительная черта крепкого инженера.
</p>

<h3>Механика работы оператора new</h3>

<p>
  Когда функция вызывается как конструктор с помощью <code>new</code> (например, <code>const obj = new F()</code>), под капотом JS выполняет ровно четыре шага:
</p>

<p>
  1. Создание: В памяти создается новый пустой объект.
</p>

<p>
  2. Связывание прототипа: Внутреннему скрытому свойству <code>[[Prototype]]</code> этого нового объекта присваивается ссылка на объект, который лежит в свойстве <code>F.prototype</code> на момент вызова.
</p>

<p>
  3. Инициализация <code>this</code>: Функция F вызывается, и контекст <code>this</code> жестко привязывается к новосозданному объекту. Внутри функции этот объект обычно наполняется свойствами.
</p>

<p>
  4. Возврат: Если функция-конструктор явно возвращает другой объект (через <code>return { ... }</code>), оператор <code>new</code> вернет этот другой объект. Во всех остальных случаях (если нет <code>return</code>, возвращается примитив или <code>return</code> пустой), <code>new</code> вернет созданный <code>this</code>.
</p>

<h3>Суть свойства F.prototype</h3>
<p>
  Здесь часто возникает путаница, поэтому важно зафиксировать:
</p>

<p>
  Это просто свойство. У любой обычной функции (кроме стрелочных) по умолчанию есть свойство с именем "prototype".
</p>

<p>
  Это <strong>не прототип самой функции</strong>. Свойство <code>F.prototype</code> никак не влияет на саму функцию <code>F</code>. Оно используется только оператором <code>new</code> для установки <code>[[Prototype]]</code> новым объектам.
</p>

<p>
  Состояние по умолчанию. Изначально <code>F.prototype</code> — это объект с единственным свойством <code>constructor</code>, которое ссылается обратно на саму функцию <code>F</code>:
</p>

<code class="code">
  F.prototype = {
    constructor: F
  };
</code>

<p class="info info--blue">
  Таким образом, свойство <code>F.prototype</code> никак не влияет на саму функцию <code>F</code> и используется только оператором <code>new</code> для установки <code>[[Prototype]]</code> новым объектам.
  <br>
  <code>F.prototype</code> — это просто шаблон для новых объектов, созданных через <code>new F()</code>.
  <br>
  Если вы не изменяете <code>F.prototype</code>, все объекты, созданные через <code>new F()</code>, будут наследовать от этого объекта с единственным свойством <code>constructor</code>.
</p>

<h3>Критические нюансы и "грабли":</h3>
<p>
  1. Связь фиксируется в момент создания.
  <br>
  Если после создания <code>obj = new F()</code> ты полностью переопределишь свойство <code>F.prototype = { ... }</code>, созданный <code>obj</code> продолжит ссылаться на старый объект прототипа. Новые объекты через <code>new F()</code> будут получать уже новый прототип.
</p>

<p>
  2. Мутация vs Перезапись.
  <br>
  Если ты не перезаписываешь <code>F.prototype</code> целиком, а мутируешь его (например, <code>F.prototype.sayHi = function() {}</code>), то старые объекты увидят этот метод, так как они ссылаются на тот же самый объект в памяти.
</p>

<p>
  3. Потеря constructor.
  <br>
  Если ты решаешь полностью заменить объект прототипа <code>F.prototype = { method1() {} }</code>, ты затираешь дефолтное свойство <code>constructor</code>. Чтобы не ломать экосистему и проверки <code>instanceof</code>, правильным подходом будет либо добавлять методы точечно (<code>F.prototype.method = ...</code>), либо вручную восстанавливать <code>constructor</code>:
</p>

<code class="code">
  F.prototype = {
    constructor: F,
    method1() {}
  };
</code>
