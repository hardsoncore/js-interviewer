<h3>Общий принцип работы (Web Storage API)</h3>

<p>И <strong>localStorage</strong>, и <strong>sessionStorage</strong> являются частью Web Storage API. У них идентичный интерфейс и одинаковая механика работы "под капотом":</p>

<p>
  1. <strong>Формат данных:</strong> Хранят данные исключительно в формате ключ-значение (key-value).
</p>
<p>
  2. <strong>Типизация:</strong> И ключи, и значения всегда конвертируются в строки. Если нужно сохранить объект или массив, его необходимо сериализовать (<code>JSON.stringify()</code>), а при чтении — распарсить (<code>JSON.parse()</code>).
</p>
<p>
  3. <strong>Синхронность:</strong> Обе API работают синхронно. Это значит, что запись большого объема данных может заблокировать главный поток (Main Thread) браузера.
</p>
<p>
  4. <strong>Привязка к Origin:</strong> Данные жестко привязаны к источнику по формуле:
  <br>
  <code>Origin = протокол + домен + порт</code>
  <br>
  <br>
  Таким образом, сайт <code>https://example.com</code> не может прочитать сторадж <code>http://example.com</code> или <code>https://api.example.com</code>.
</p>
<p>
  5. <strong>Лимиты:</strong> В большинстве современных браузеров квота составляет около 5 МБ на один Origin.
</p>

<h3>Основные различия и рекомендации по использованию</h3>

<p>
  1. <strong>Время жизни данных:</strong>
  <ul>
    <li><strong>localStorage:</strong> Данные сохраняются бессрочно, пока пользователь не удалит их вручную или не очистит кэш браузера.</li>
    <li><strong>sessionStorage:</strong> Данные сохраняются только в рамках одной сессии. Они удаляются при закрытии вкладки или окна браузера.</li>
  </ul>
</p>
<p>
  2. <strong>Доступность между вкладками:</strong>
  <ul>
    <li><strong>localStorage:</strong> Доступен во всех вкладках и окнах, открытых на том же Origin. Изменения в localStorage в одной вкладке могут быть обнаружены в других вкладках через событие <code>storage</code>.</li>
    <li><strong>sessionStorage:</strong> Доступен только в той вкладке, где был создан. Другие вкладки не видят данные sessionStorage.</li>
  </ul>
</p>
<p>
  3. <strong>Использование:</strong>
  <ul>
    <li><strong>localStorage:</strong> Идеально подходит для хранения данных, которые должны сохраняться между сессиями, например, пользовательские настройки, темы оформления, токены аутентификации (хотя для токенов лучше использовать HttpOnly cookies).</li>
    <li><strong>sessionStorage:</strong> Подходит для временных данных, которые нужны только в рамках одной сессии, например, данные формы, которые не должны сохраняться после закрытия вкладки.</li>
  </ul>
</p>

<h3>Шпаргалка по методам (API)</h3>
<p>Так как интерфейс у них общий (Storage), методы абсолютно одинаковые. Вот базовый CRUD:</p>

<code class="code">
  // 1. Запись (Create / Update)
  localStorage.setItem('theme', 'dark');

  // 2. Чтение (Read)
  const theme = localStorage.getItem('theme'); // 'dark'

  // 3. Удаление одного элемента (Delete)
  localStorage.removeItem('theme');

  // 4. Полная очистка хранилища
  sessionStorage.clear();
</code>

<h3>Важные нюансы безопасности и архитектуры</h3>

<p>
  <strong>Уязвимость к XSS (Cross-Site Scripting):</strong><br>
  Любой JS-код, выполняющийся на странице, имеет доступ к Web Storage. Никогда не храни там чувствительные данные: пароли, номера кредитных карт или персональные данные.
  (Споры насчет хранения JWT-токенов в localStorage идут постоянно. Это удобно, но менее безопасно, чем хранение в httpOnly куках, так как токен могут украсть через XSS уязвимость).
</p>
<p>
  <strong>Синхронная блокировка:</strong><br>
  Не пиши и не читай огромные массивы данных (мегабайты) из стораджа в цикле. Это заморозит UI (особенно критично для рендеринга во Vue/Angular). Если данных много — лучше посмотреть в сторону IndexedDB.
</p>
