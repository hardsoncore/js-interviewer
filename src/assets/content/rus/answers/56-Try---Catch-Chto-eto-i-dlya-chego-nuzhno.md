<h3>Зачем нужен Try...Catch?</h3>

<p><span class="accent">Try...Catch</span> - это конструкция в JavaScript, которая позволяет обрабатывать ошибки, возникающие во время выполнения кода. Она состоит из двух основных блоков: <code>try</code> и <code>catch</code>.</p>

<p>Код без ошибок - это идеал, к которому мы стремимся. Однако в реальной жизни всегда есть вероятность возникновения ошибок. Например, сервер может упасть, пользователь может ввести некорректные данные, или API может вернуть битый JSON. Если не обрабатывать такие ситуации, выполнение скрипта просто прерывается, и пользователь видит "белый экран".</p>

<h3>Предотвращение аварийной остановки (Graceful Failure)</h3>
<p>Главная задача — не дать приложению «умереть». Когда внутри блока <code>try</code> происходит ошибка, выполнение кода в этом блоке останавливается, но управление передается в <code>catch</code>. Остальной скрипт продолжает работать.</p>

<p>Пример из жизни: Парсинг данных. Если данные придут в неверном формате, <code>JSON.parse</code> выбросит исключение. Без <code>try...catch</code> это «повесит» фронтенд.</p>

<code class="code">
  try {
    const data = JSON.parse(responseFromServer); // Если тут ошибка...
    process(data);
  } catch (error) {
    console.error("Ошибка при обработке данных:", error.message);
    showNotification("Извините, данные повреждены."); // Приложение живет дальше
  }
</code>

<h3>Блоки Try и Catch: Основы</h3>
<p>Блок <code>try</code> содержит код, который может вызвать ошибку, а блок <code>catch</code> выполняется, если в блоке <code>try</code> возникает ошибка. В блоке <code>catch</code> мы можем получить объект ошибки и использовать его для получения информации о том, что произошло не так.</p>

<h3>Блок finally: Чистота после бури</h3>
<p>Есть задачи, которые должны быть выполнены всегда, независимо от того, случилась ошибка или нет. Для этого нужен <code>finally</code>.</p>

<p>Примеры использования:</p>
<ul>
  <li>Закрытие соединений.</li>
  <li>Выключение индикатора загрузки (spinner). Тебе в любом случае нужно убрать «крутилку» с экрана, загрузились данные или упали с ошибкой.</li>
</ul>

<code class="code">
  try {
    showSpinner();
    const data = await fetchData();
    process(data);
  } catch (error) {
    console.error("Ошибка при загрузке данных:", error.message);
    showNotification("Не удалось загрузить данные.");
  } finally {
    hideSpinner(); // Убираем крутилку в любом случае
  }
</code>

<h3>Советы по использованию:</h3>
<p><strong>Не «глотай» ошибки:</strong> Никогда не оставляй <code>catch (e) {}</code> пустым. Если ты не знаешь, что делать с ошибкой, хотя бы выведи её в консоль. Иначе отладка превратится в ад.</p>

<p><strong>Будь специфичен:</strong> Не оборачивай весь код в один гигантский <code>try...catch</code>. Оборачивай только те участки, где ошибка вероятна (сетевые запросы, работа с DOM, сложные вычисления).</p>

<p><strong>Выбрасывай свои ошибки:</strong> Ты можешь сам генерировать исключения с помощью <code>throw new Error('Something went wrong')</code>. Это отличный способ передать сигнал о проблеме из глубин бизнес-логики наверх, к UI-компоненту.</p>
