<h3>Вступ</h3>
<p><span class="accent">DOM (Document Object Model)</span> — об'єктна модель документа: браузер парсить HTML і будує з нього живе дерево вузлів, а JavaScript через API цього дерева читає і змінює сторінку. «Живе» — означає, змінив вузол, і браузер перемалював сторінку. <span class="accent">DOM-події</span> — механізм реакції на дії користувача і браузера: клік, введення, скрол.</p>

<p class="info"><strong>Головна думка:</strong> подія не спрацьовує «в точці» — вона проходить шлях по дереву: <strong>занурення → ціль → спливання</strong>. На спливанні побудований головний практичний патерн — <strong>делегування</strong>: один обробник на батькові замість сотень на нащадках.</p>

<h3>Три фази події (Event Flow)</h3>
<ul>
  <li><strong>Занурення (Capturing)</strong> — подія спускається від <code>window</code> і <code>document</code> вниз до цілі.</li>
  <li><strong>Цільова фаза (Target)</strong> — подія досягла найглибшого елемента, на якому відбулася.</li>
  <li><strong>Спливання (Bubbling)</strong> — подія піднімається назад до кореня, дорогою викликаючи обробники батьків.</li>
</ul>
<p><code>addEventListener</code> за замовчуванням слухає фазу спливання. Щоб перехопити подію на зануренні, передають третій аргумент <code>{ capture: true }</code>.</p>

<h3>target vs currentTarget і зупинка</h3>
<ul>
  <li><code>event.target</code> — елемент, на якому подія відбулася (найглибший);</li>
  <li><code>event.currentTarget</code> — елемент, на якому висить поточний обробник;</li>
  <li><code>event.stopPropagation()</code> — обриває подальший шлях події по дереву.</li>
</ul>

<h3>Делегування подій (Event Delegation)</h3>
<p>Замість обробника на кожному елементі списку вішаємо один на спільного батька: спливання само принесе подію нагору, а <code>event.target</code> підкаже, де саме клікнули.</p>
<code class="code">
  list.addEventListener('click', (event) => {
    const item = event.target.closest('li');
    if (!item) return; // клік повз елементи списку

    selectItem(item);
  });
</code>
<p>Дві вигоди: економія пам'яті (один слухач замість тисяч) і робота з динамічним DOM — елементи, додані пізніше, не потрібно підписувати заново: батько і так упіймає їхні події.</p>

<p class="info info--blue">У декларативних фреймворках вішати <code>(click)</code> / <code>@click</code> на кожен елемент списку — нормальний підхід: код читабельний, контекст передається напряму. Делегування вмикай усвідомлено — для величезних списків, сирого HTML і сторонніх бібліотек (розбір у Deep Dive).</p>

<p class="info info--orange">Не всі події спливають: <code>focus</code>, <code>blur</code>, <code>mouseenter</code>, <code>mouseleave</code>. Для делегування фокуса є спливаючі аналоги <code>focusin</code>/<code>focusout</code>. І не плутай: <code>stopPropagation()</code> зупиняє шлях по дереву, а <code>preventDefault()</code> скасовує типову дію браузера.</p>

<p class="deep-dive">Поглиблений конспект</p>

<h3>Навіщо потрібна фаза занурення</h3>
<p>На практиці capturing використовують рідко: перехопити подію раніше за всі інші обробники (аналітика, тимчасове блокування інтерфейсу) або впіймати на предкові подію, що не спливає, — фаза занурення проходить через предків завжди, навіть якщо спливання у події немає.</p>
<p>Зорієнтуватися, де зараз подія, допомагає <code>event.eventPhase</code> (1 — занурення, 2 — ціль, 3 — спливання). А <code>event.stopImmediatePropagation()</code> обриває не лише шлях по дереву, а й решту обробників на поточному елементі.</p>

<h3>Опції addEventListener</h3>
<ul>
  <li><code>capture</code> — слухати на фазі занурення;</li>
  <li><code>once</code> — обробник зніметься сам після першого спрацьовування;</li>
  <li><code>passive</code> — обіцянка не викликати <code>preventDefault()</code>: браузер не чекає виконання JS і одразу прокручує сторінку. Критично для <code>touchstart</code> і <code>wheel</code>, тому в Chrome для них passive увімкнений за замовчуванням;</li>
  <li><code>signal</code> — прив'язка до <code>AbortController</code>: один виклик <code>controller.abort()</code> знімає цілу групу обробників без зберігання посилань на функції.</li>
</ul>

<h3>Коли делегування справді необхідне</h3>
<p><strong>Велика кількість елементів.</strong> Сотні рядків таблиці, комірки складного календаря: тисячі слухачів — це зайва пам'ять і час на підписку/відписку під час кожного ререндеру.</p>
<p><strong>Рендеринг сирого HTML.</strong> Якщо розмітка приходить з бекенду рядком і вставляється через <code>[innerHTML]</code> (Angular) або <code>v-html</code> (Vue), фреймворк не компілює всередині неї свої директиви — <code>@click</code> там просто не запрацює. Єдиний спосіб ловити кліки всередині такого блока — слухач на обгортці та перевірка <code>event.target</code>.</p>
<p><strong>Сторонні бібліотеки.</strong> Плагіни на Vanilla JS (графіки D3.js, карти Leaflet) генерують DOM-вузли в обхід рушія фреймворка. Делегування на кореневій обгортці — найнадійніший спосіб зв'язати їхні події з методами компонента.</p>

<h3>Фреймворки і Shadow DOM</h3>
<p>React сам побудований на делегуванні: синтетичні події слухаються не на елементах, а на кореневому контейнері застосунку (до React 17 — на <code>document</code>). Тому обробник «на кожному елементі» в JSX майже нічого не коштує.</p>
<p>Shadow DOM додає ретаргетинг: коли подія спливає з тіньового дерева назовні, <code>event.target</code> підміняється на хост-елемент, щоб не розкривати нутрощі компонента. Реальний шлях події повертає <code>event.composedPath()</code>, а чи перетинає вона межу тіні — визначає прапорець <code>composed</code>.</p>
