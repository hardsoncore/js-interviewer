<h3>Визначення</h3>
<p><span class="accent">__proto__</span> — це історичний гетер/сетер (властивість доступу), який дозволяє прочитати або змінити приховану внутрішню властивість об'єкта <code>[[Prototype]]</code>.</p>

<p>У JavaScript успадкування реалізовано через прототипи. <code>[[Prototype]]</code> — це фізичне посилання на інший об'єкт (або <code>null</code>), від якого поточний об'єкт успадковує властивості та методи.</p>

<h3>Як працює ланцюжок (Prototype Chain)</h3>
<p>Коли інтерпретатор намагається прочитати властивість або викликати метод об'єкта, відбувається наступне:</p>

<p>1. Йде пошук властивості в самому об'єкті.</p>

<p>2. Якщо властивість не знайдено, пошук переходить до об'єкта, на який посилається <code>__proto__</code>.</p>

<p>3. Цей процес повторюється вгору по ланцюжку, поки властивість не буде знайдено, або поки <code>__proto__</code> не виявиться рівним <code>null</code> (зазвичай це стається після <code>Object.prototype</code>).</p>

<h3>__proto__ vs prototype (Головна плутанина)</h3>
<p>Це два абсолютно різних поняття, які працюють у тандемі при створенні об'єктів:</p>

<p><strong>prototype</strong> — це властивість функцій-конструкторів (та класів). Вона існує до створення екземпляра і містить об'єкт, який буде призначений як прототип для всіх майбутніх екземплярів, створених через <code>new</code>.</p>

<p><strong>__proto__</strong> — це посилання всередині <strong>вже створеного екземпляра</strong>, яке вказує на його прототип.</p>

<p class="info info--blue">
  Зв'язок простий: instance.__proto__ === Constructor.prototype
</p>

<p>Наприклад:</p>
<code class="code">
  function Person(name) {
    this.name = name;
  }

  Person.prototype.greet = function() {
    return `Привіт, мене звати ${this.name}`;
  };

  const alice = new Person('Alice');
  console.log(alice.greet()); // "Привіт, мене звати Alice"
  console.log(alice.__proto__ === Person.prototype); // true
</code>

<h3>Сучасний стандарт (Чому __proto__ це Legacy)</h3>

<p>Хоча <code>__proto__</code> і був стандартизований в ES6 (виключно заради зворотної сумісності з браузерами), використовувати його в робочому коді — моветон.</p>

<p>Сучасні альтернативи:</p>

<p><strong>Читання:</strong> Замість <code>obj.__proto__</code> використовуй <code>Object.getPrototypeOf(obj)</code>.</p>

<p><strong>Запис:</strong> Замість <code>obj.__proto__ = newProto</code> використовуй <code>Object.setPrototypeOf(obj, newProto)</code>.</p>

<p><strong>Створення з нуля:</strong> Найкращий спосіб задати прототип — при створенні об'єкта: <code>Object.create(newProto)</code>.</p>

<h3>Обережно: продуктивність</h3>
<p>Зміна <code>[[Prototype]]</code> у вже існуючого об'єкта (хоч через <code>__proto__</code>, хоч через <code>Object.setPrototypeOf</code>) — це катастрофічно повільна операція. Сучасні JS-движки (наприклад, V8) оптимізують доступ до властивостей, створюючи приховані класи (hidden classes). Зміна прототипу «на льоту» руйнує ці оптимізації, змушуючи движок деоптимізувати код.</p>
