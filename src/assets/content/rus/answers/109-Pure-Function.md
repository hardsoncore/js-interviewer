<h3>Формулировка для собеседования</h3>

<p>
  <span class="accent">Чистая функция</span> — это функция, которая при одинаковых аргументах всегда возвращает одинаковый результат (отличается детерминированностью) и не производит никаких побочных эффектов (Side Effects) во внешней среде.
</p>

<p class="info info--blue">
  <strong>Чистая функция</strong> не мутирует внешние переменные или аргументы, не влияет на состояние приложения и не делает запросы к сторонним API. Благодаря этому, чистые функции максимально предсказуемы, их очень легко покрывать Unit-тестами и их можно кешировать (мемоизировать).
</p>

<p class="info info--orange">Важно понимать, что <strong>чистые функции</strong> — это не просто "хорошая практика". Это фундаментальный строительный блок для создания надежного, масштабируемого и легко поддерживаемого кода, особенно в больших приложениях с множеством взаимодействующих компонентов.</p>

<hr />

<h3>Техническая механика (Два главных правила)</h3>

<p>Чтобы функция считалась чистой, она должна строго соблюдать независимость по двум фронтам:</p>

<ul>
  <li>
    <strong>1. Детерминированность (Предсказуемость):</strong>
    При одинаковых входных аргументах функция <em>всегда</em> возвращает один и тот же результат. На её вывод не могут влиять глобальные переменные, время, случайные числа или состояние сети.
  </li>
  <li>
    <strong>2. Отсутствие побочных эффектов (No Side Effects):</strong>
    Функция не должна мутировать (изменять) внешние переменные или свои аргументы. Она не должна трогать DOM, отправлять HTTP-запросы, выводить что-то в console или записывать в базу данных. Вся её работа замыкается строго внутри неё самой, возвращая новый результат.
  </li>
</ul>

<hr />

<h3>Практическая польза (Почему мы их любим)</h3>

<ul>
  <li><strong>Легкость тестирования (Unit-тесты):</strong> Не нужно мокать сложные внешние зависимости или воссоздавать запутанное глобальное состояние. Передал нужные аргументы — проверил ожидаемый результат.</li>
  <li><strong>Читаемость и надежность:</strong> Ты точно знаешь, что вызов функции-помощника где-то сбоку ничего не сломает в соседнем компоненте. Код становится декларативным.</li>
  <li><strong>Кеширование (Мемоизация):</strong> Если для аргумента "A" всегда получается результат "B", мы можем его запомнить. При повторном вызове с "A" мы просто отдаем "B" из кеша, экономя ресурсы. Это часто используется в селекторах (например, в NgRx или Redux).</li>
  <li><strong>Конкурентность:</strong> Поскольку нет общего изменяемого состояния, такие функции безопасно использовать при параллельных вычислениях (например, в Web Workers).</li>
  <li><strong>Предсказуемый UI и стейт-менеджмент:</strong> В фреймворках типа Vue или Angular, чистые функции помогают создавать предсказуемые компоненты и селекторы, которые не зависят от внешних факторов и всегда возвращают один и тот же результат для одних и тех же входных данных.</li>
</ul>

<h3>Примеры кода</h3>

<h4>Нечистая функция (Impure)</h4>
<p>Эта функция зависит от внешней переменной и изменяет её (побочный эффект):</p>
<code class="code">
  let total = 0;

  function addImpure(value) {
    total += value; // Мутирует внешнее состояние
    return total;
  }

  addImpure(5); // Вернет 5
  addImpure(5); // Вернет 10 (при тех же аргументах результат отличается!)
</code>

<p>Второй частый пример нечистой функции — мутация своих же аргументов:</p>
<code class="code">
  function addElementImpure(arr, el) {
    arr.push(el); // Мутирует входящий массив
    return arr;
  }
</code>

<h4>Чистая функция (Pure)</h4>
<p>Зависит только от аргументов и всегда возвращает новый результат, ничего не ломая вокруг:</p>
<code class="code">
  function addPure(a, b) {
    return a + b; // Никаких side-effects, только вычисление на основе аргументов
  }

  addPure(5, 5); // Всегда 10
  addPure(5, 5); // Всегда 10
</code>

<p>Исправление второго примера с массивом, чтобы функция стала чистой (без мутаций):</p>
<code class="code">
  function addElementPure(arr, el) {
    return [...arr, el]; // Возвращаем абсолютно новый экземпляр массива
  }
</code>

<h3>Ссылочная прозрачность (Referential Transparency)</h3>

<p>Чистые функции обладают свойством <span class="accent">ссылочной прозрачности</span>, что означает: любой вызов функции можно заменить её результатом без изменения поведения программы. Это позволяет легко оптимизировать код, например, заменяя вызовы на константы или используя мемоизацию.</p>

<p>Это фундамент функционального программирования и понятие, неразрывно связанное с чистыми функциями (Pure Functions). Если функция при одних и тех же входных данных всегда возвращает один и тот же результат и не создает <strong>побочных эффектов (side-effects)</strong>, она обладает ссылочной прозрачностью.</p>

<code class="code">
  // Ссылочно прозрачная функция
  const multiply = (a: number, b: number) => a * b;

  // Мы можем в коде заменить multiply(3, 4) на 12, и ничего не сломается.
  let total = multiply(3, 4) + 10; // то же самое, что и: let total = 12 + 10;

  // НЕ ссылочно прозрачная функция
  let bonus = 5;
  const calculateTotal = (price: number) => price + bonus;
  // Мы не можем просто заменить calculateTotal(10) на 15,
  // потому что значение переменной bonus может измениться в любой момент.
</code>
