<h3>Що таке DOCTYPE?</h3>
<p>
  <span class="accent">&lt;!DOCTYPE html></span> — це декларація (не HTML-тег), яка має стояти
  найпершим рядком документа. Вона повідомляє браузеру, за якими правилами парсити та рендерити сторінку.
</p>

<p class="info">
  <strong>Головна думка:</strong> сьогодні DOCTYPE — це перемикач режимів рендерингу.
  З ним браузер працює у <strong>standards mode</strong> (за сучасними стандартами),
  без нього — у <strong>quirks mode</strong>, емулюючи баги браузерів кінця 90-х.
</p>

<code class="code">
  &lt;!DOCTYPE html>
  &lt;html>
    ...
  &lt;/html>
</code>

<h3>Навіщо потрібен DOCTYPE?</h3>
<ul>
  <li>
    Вмикає <strong>standards mode</strong> — сторінка рендериться передбачувано
    й однаково в усіх браузерах.
  </li>
  <li>
    Без нього браузер переходить у <strong>quirks mode</strong>: інша боксова модель (як у старому IE),
    інакше обчислюються розміри inline-елементів і таблиць — верстка «пливе».
  </li>
  <li>
    Потрібен для валідації: валідатор перевіряє код відповідно до оголошеної версії HTML.
  </li>
</ul>

<p class="info info--orange">
  DOCTYPE не «підключає» HTML5-фічі: нові теги та API працюють і без нього.
  Він впливає саме на режим рендерингу (насамперед на CSS-розкладку),
  тому його відсутність ламає верстку, а не JavaScript.
</p>

<h3>Види DOCTYPE</h3>
<p>
  До HTML5 декларація посилалася на <span class="accent">DTD</span> (Document Type Definition) —
  формальний опис граматики конкретної версії мови. Звідси громіздкі варіанти:
  <strong>HTML 4.01</strong> та <strong>XHTML 1.0</strong> у редакціях Strict / Transitional / Frameset, а також XHTML 1.1.
</p>

<p>
  В HTML5 декларацію скоротили до <code>&lt;!DOCTYPE html></code> — мінімального рядка,
  який гарантовано вмикає standards mode в усіх браузерах. Сьогодні використовується лише він.
</p>

<h3>Чи можна обійтися без DOCTYPE?</h3>
<p>
  Технічно — так, сторінка відрендериться, але в quirks mode, причому в кожного браузера
  свої «примхи»: розкладка відрізнятиметься, а налагоджувати такі розбіжності важко.
</p>

<p class="info info--blue">
  На практиці: завжди починайте документ із <code>&lt;!DOCTYPE html></code>.
  Регістр не має значення (<code>&lt;!doctype html></code> теж валідний),
  але декларація має йти до будь-якого іншого вмісту сторінки.
</p>

<p class="deep-dive">Поглиблений конспект</p>

<h3>Режими рендерингу: їх насправді три</h3>
<p>
  Браузер обирає режим «сніфінгом» DOCTYPE — за його точним текстом:
</p>
<ul>
  <li>
    <strong>No-quirks (standards) mode</strong> — вмикається сучасним <code>&lt;!DOCTYPE html></code>
    та старими Strict-DTD. Повна відповідність специфікаціям.
  </li>
  <li>
    <strong>Limited-quirks (almost standards) mode</strong> — вмикається Transitional/Frameset DTD з URI.
    Відрізняється від standards лише рендерингом зображень у комірках таблиць:
    картинка притискається до низу комірки без зазору під базовою лінією тексту.
  </li>
  <li>
    <strong>Quirks mode</strong> — за відсутності DOCTYPE або застарілої/неповної декларації.
  </li>
</ul>

<h4>Що конкретно ламається в quirks mode</h4>
<ul>
  <li>
    Боксова модель за зразком IE5: <code>width</code>/<code>height</code> включають
    <code>padding</code> і <code>border</code> (як <code>box-sizing: border-box</code>,
    але примусово і для всіх елементів).
  </li>
  <li>
    Розміри без одиниць вимірювання трактуються як пікселі (<code>width: 100</code> спрацює).
  </li>
  <li>
    Стилі шрифту не успадковуються всередину таблиць — текст у <code>&lt;table></code>
    ігнорує <code>font-family</code> та <code>font-size</code> батька.
  </li>
  <li>
    Інакше працюють <code>line-height</code>, вертикальне вирівнювання inline-контенту
    та колірні значення в нестандартних форматах.
  </li>
</ul>

<p>
  Перевірити поточний режим із JavaScript можна через <code>document.compatMode</code>:
  <code>"CSS1Compat"</code> — standards/limited-quirks, <code>"BackCompat"</code> — quirks mode.
</p>

<h3>Історична довідка: звідки це все взялося</h3>
<p>
  У 90-ті браузери рендерили сторінки з розбіжностями від стандартів (найвідоміший приклад —
  боксова модель IE). Коли браузери почали виправляти поведінку під специфікації,
  виникла проблема: мільйони старих сайтів були зверстані під баги і «зламалися б» за чесного рендерингу.
  Рішення — <strong>DOCTYPE switching</strong> (вперше в IE5/Mac): новий коректний рендеринг
  вмикається лише за наявності «сучасного» DOCTYPE, а старі сторінки без нього
  продовжують оброблятися по-старому. Так quirks mode став музеєм багів, який браузери
  зобов'язані підтримувати досі.
</p>

<p>
  Так виглядала декларація до HTML5:
</p>

<code class="code">
  &lt;!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
    "http://www.w3.org/TR/html4/strict.dtd">
</code>

<p>
  DTD — спадщина SGML, на якому формально був заснований HTML до версії 4.01 включно.
  HTML5 відмовився від SGML: його парсер описано у специфікації алгоритмічно, DTD більше не потрібен,
  тому декларація виродилася в короткий маркер «рендери за стандартами».
</p>

<p class="info info--blue">
  XHTML-документ, відданий з MIME-типом <code>application/xhtml+xml</code>,
  завжди рендериться у standards mode — DOCTYPE-сніфінг застосовується лише до <code>text/html</code>.
</p>
