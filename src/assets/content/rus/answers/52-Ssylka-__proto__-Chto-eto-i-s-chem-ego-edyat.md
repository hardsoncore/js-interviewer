<h3>Что такое __proto__</h3>
<p><span class="accent">__proto__</span> — это исторический геттер/сеттер, через который можно прочитать или изменить скрытое свойство объекта <code>[[Prototype]]</code> — ссылку на прототип, у которого движок ищет отсутствующие свойства.</p>

<p class="info"><strong>Главная мысль:</strong> <code>__proto__</code> — это не сам прототип, а устаревшая «дверца» к нему. Прототип живёт во внутреннем слоте <code>[[Prototype]]</code>, а стандартный доступ сегодня — <code>Object.getPrototypeOf / setPrototypeOf</code>.</p>

<h3>__proto__ vs [[Prototype]] vs F.prototype</h3>
<p>Три понятия, которые постоянно путают:</p>
<ul>
  <li><code>[[Prototype]]</code> — внутренний скрытый слот каждого объекта: ссылка на прототип или <code>null</code>. Из кода напрямую недоступен.</li>
  <li><code>__proto__</code> — аксессор для чтения и записи этого слота у уже созданного объекта.</li>
  <li><code>F.prototype</code> — обычное свойство функции-конструктора: объект, который станет <code>[[Prototype]]</code> экземпляров, созданных через <code>new F()</code>. На прототип самой функции <code>F</code> оно не влияет.</li>
</ul>

<code class="code">
  function Person(name) {
    this.name = name;
  }

  const alice = new Person('Alice');

  // new записал Person.prototype в слот [[Prototype]] экземпляра
  console.log(alice.__proto__ === Person.prototype);              // true
  console.log(Object.getPrototypeOf(alice) === Person.prototype); // true
</code>

<h3>Современные альтернативы</h3>
<ul>
  <li>Чтение: <code>Object.getPrototypeOf(obj)</code>.</li>
  <li>Запись: <code>Object.setPrototypeOf(obj, proto)</code>.</li>
  <li>Создание с нужным прототипом сразу: <code>Object.create(proto)</code> — лучший вариант, объект рождается с правильной цепочкой.</li>
</ul>
<p>Сам <code>__proto__</code> стандартизирован в ES6 только ради обратной совместимости со старым кодом — в новом коде ему не место.</p>

<p class="info info--blue">Правило: <code>__proto__</code> — только подсмотреть в консоли при отладке. В коде — <code>Object.getPrototypeOf / create</code>, а менять прототип живого объекта — не делать вовсе.</p>

<h3>Производительность: почему нельзя менять прототип на лету</h3>
<p>Смена <code>[[Prototype]]</code> у живого объекта — одна из самых медленных операций в JS, каким бы способом её ни делать. Движки оптимизируют доступ к свойствам через hidden classes и инлайн-кэши, которые опираются на стабильность формы объекта и его цепочки. Подмена прототипа ломает эти кэши и деоптимизирует весь код, работающий с объектом. Поэтому прототип задаётся один раз — при создании.</p>

<p class="info info--orange">Ловушка: у стрелочной функции нет свойства <code>prototype</code>, но <code>__proto__</code> у неё есть — как у любого объекта. <code>prototype</code> есть только у функций, способных работать конструктором.</p>

<h3>Почему __proto__ вообще работает: аксессор на Object.prototype</h3>
<p><code>__proto__</code> — не собственное свойство каждого объекта, а геттер/сеттер, объявленный один раз на <code>Object.prototype</code>. Обращение <code>obj.__proto__</code> находит этот аксессор по цепочке прототипов и вызывает его с <code>this = obj</code>. Отсюда следствие: если <code>Object.prototype</code> в цепочке нет — «дверца» исчезает:</p>
<code class="code">
  const dict = Object.create(null); // объект без прототипа

  dict.__proto__ = { hacked: true };
  console.log(dict.hacked);    // undefined — прототип НЕ подменился
  console.log(dict.__proto__); // { hacked: true } — обычное свойство-данные
</code>
<p>Аксессор не найден, поэтому присваивание просто создало собственное свойство с именем <code>__proto__</code>. Именно поэтому <code>Object.create(null)</code> — безопасный словарь для пользовательских ключей.</p>

<h3>Prototype Pollution — атака через __proto__</h3>
<p>Классическая уязвимость: код рекурсивно мёржит в объект внешние данные (deep merge настроек, query-параметров, JSON с бэкенда). Злоумышленник передаёт ключ <code>"__proto__"</code>, присваивание <code>obj[key] = value</code> вызывает сеттер — и свойства записываются прямо в <code>Object.prototype</code>, «появляясь» у всех объектов приложения. Так подменяют флаги вроде <code>isAdmin</code> или ломают логику целиком.</p>
<p>Нюанс: сам <code>JSON.parse('{"__proto__": {...}}')</code> безопасен — парсер создаёт обычное свойство-данные, минуя сеттер. Опасен именно последующий наивный merge по ключам. Защита: <code>Object.create(null)</code> или <code>Map</code> для словарей, фильтрация ключей <code>__proto__</code>, <code>constructor</code>, <code>prototype</code>.</p>

<h3>Edge cases сеттера</h3>
<ul>
  <li>Сеттер принимает только объект или <code>null</code>: присваивание примитива (<code>obj.__proto__ = 42</code>) молча игнорируется.</li>
  <li>Попытка замкнуть цепочку в цикл (<code>a.__proto__ = b; b.__proto__ = a</code>) бросает <code>TypeError: Cyclic __proto__ value</code>.</li>
  <li>У нерасширяемого объекта (<code>Object.preventExtensions</code>) смена прототипа бросает <code>TypeError</code>.</li>
</ul>

<h3>История: Annex B</h3>
<p><code>__proto__</code> появился в 1990-х как нестандартное расширение движка SpiderMonkey (Netscape), расползся по остальным движкам, и веб стал на него полагаться. В ES6 (2015) его пришлось узаконить — но не в основной спецификации, а в Annex B, разделе legacy-функций для совместимости с вебом. Официальные замены: <code>Object.getPrototypeOf</code> — ещё ES5, <code>Object.setPrototypeOf</code> — ES6.</p>

<h3>Что именно ломается в движке при смене прототипа</h3>
<p>V8 описывает структуру каждого объекта скрытым классом (hidden class / shape): какие свойства, по каким смещениям, какой прототип. Оптимизированный машинный код и инлайн-кэши привязываются к конкретному скрытому классу: «у объектов этой формы метод лежит там-то». Смена прототипа переводит объект на новый скрытый класс — все участки кода, видевшие объект, становятся полиморфными или мегаморфными, и движок сбрасывает оптимизации (deoptimization). Медленной становится не сама операция <code>setPrototypeOf</code>, а весь последующий доступ к свойствам этого объекта.</p>
