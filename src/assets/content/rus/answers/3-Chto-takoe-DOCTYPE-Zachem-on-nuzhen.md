<h3>Что такое DOCTYPE?</h3>
<p>
  <span class="accent">&lt;!DOCTYPE html></span> — это декларация (не HTML-тег), которая должна стоять
  самой первой строкой документа. Она сообщает браузеру, по каким правилам парсить и рендерить страницу.
</p>

<p class="info">
  <strong>Главная мысль:</strong> сегодня DOCTYPE — это переключатель режимов рендеринга.
  С ним браузер работает в <strong>standards mode</strong> (по современным стандартам),
  без него — в <strong>quirks mode</strong>, эмулируя баги браузеров конца 90-х.
</p>

<code class="code">
  &lt;!DOCTYPE html>
  &lt;html>
    ...
  &lt;/html>
</code>

<h3>Зачем нужен DOCTYPE?</h3>
<ul>
  <li>
    Включает <strong>standards mode</strong> — страница рендерится предсказуемо
    и одинаково во всех браузерах.
  </li>
  <li>
    Без него браузер уходит в <strong>quirks mode</strong>: другая боксовая модель (как в старом IE),
    иначе считаются размеры inline-элементов и таблиц — вёрстка «плывёт».
  </li>
  <li>
    Нужен для валидации: валидатор проверяет код против объявленной версии HTML.
  </li>
</ul>

<p class="info info--orange">
  DOCTYPE не «подключает» HTML5-фичи: новые теги и API работают и без него.
  Он влияет именно на режим рендеринга (в первую очередь на CSS-раскладку),
  поэтому его отсутствие ломает вёрстку, а не JavaScript.
</p>

<h3>Виды DOCTYPE</h3>
<p>
  До HTML5 декларация ссылалась на <span class="accent">DTD</span> (Document Type Definition) —
  формальное описание грамматики конкретной версии языка. Отсюда громоздкие варианты:
  <strong>HTML 4.01</strong> и <strong>XHTML 1.0</strong> в редакциях Strict / Transitional / Frameset, а также XHTML 1.1.
</p>

<p>
  В HTML5 декларацию сократили до <code>&lt;!DOCTYPE html></code> — минимальной строки,
  гарантированно включающей standards mode во всех браузерах. Сегодня используется только она.
</p>

<h3>Можно ли обойтись без DOCTYPE?</h3>
<p>
  Технически — да, страница отрендерится, но в quirks mode, причём у каждого браузера
  свои «причуды»: раскладка будет различаться, а отлаживать такие расхождения тяжело.
</p>

<p class="info info--blue">
  На практике: всегда начинайте документ с <code>&lt;!DOCTYPE html></code>.
  Регистр не важен (<code>&lt;!doctype html></code> тоже валиден),
  но декларация должна идти до любого другого содержимого страницы.
</p>

<p class="deep-dive">Углубленный конспект</p>

<h3>Режимы рендеринга: их на самом деле три</h3>
<p>
  Браузер выбирает режим «сниффингом» DOCTYPE — по его точному тексту:
</p>
<ul>
  <li>
    <strong>No-quirks (standards) mode</strong> — включается современным <code>&lt;!DOCTYPE html></code>
    и старыми Strict-DTD. Полное соответствие спецификациям.
  </li>
  <li>
    <strong>Limited-quirks (almost standards) mode</strong> — включается Transitional/Frameset DTD с URI.
    Отличается от standards только рендерингом изображений в ячейках таблиц:
    картинка прижимается к низу ячейки без зазора под базовой линией текста.
  </li>
  <li>
    <strong>Quirks mode</strong> — при отсутствии DOCTYPE или устаревшей/неполной декларации.
  </li>
</ul>

<h4>Что конкретно ломается в quirks mode</h4>
<ul>
  <li>
    Боксовая модель по образцу IE5: <code>width</code>/<code>height</code> включают
    <code>padding</code> и <code>border</code> (как <code>box-sizing: border-box</code>,
    но принудительно и для всех элементов).
  </li>
  <li>
    Размеры без единиц измерения трактуются как пиксели (<code>width: 100</code> сработает).
  </li>
  <li>
    Стили шрифта не наследуются внутрь таблиц — текст в <code>&lt;table></code>
    игнорирует <code>font-family</code> и <code>font-size</code> родителя.
  </li>
  <li>
    Иначе работают <code>line-height</code>, вертикальное выравнивание inline-контента
    и цветовые значения в нестандартных форматах.
  </li>
</ul>

<p>
  Проверить текущий режим из JavaScript можно через <code>document.compatMode</code>:
  <code>"CSS1Compat"</code> — standards/limited-quirks, <code>"BackCompat"</code> — quirks mode.
</p>

<h3>Историческая справка: откуда это всё взялось</h3>
<p>
  В 90-е браузеры рендерили страницы с расхождениями от стандартов (самый известный пример —
  боксовая модель IE). Когда браузеры начали исправлять поведение под спецификации,
  возникла проблема: миллионы старых сайтов были свёрстаны под баги и «сломались бы» при честном рендеринге.
  Решение — <strong>DOCTYPE switching</strong> (впервые в IE5/Mac): новый корректный рендеринг
  включается только при наличии «современного» DOCTYPE, а старые страницы без него
  продолжают обрабатываться по-старому. Так quirks mode стал музеем багов, который браузеры
  обязаны поддерживать до сих пор.
</p>

<p>
  Так выглядела декларация до HTML5:
</p>

<code class="code">
  &lt;!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
    "http://www.w3.org/TR/html4/strict.dtd">
</code>

<p>
  DTD — наследие SGML, на котором формально был основан HTML до версии 4.01 включительно.
  HTML5 отказался от SGML: его парсер описан в спецификации алгоритмически, DTD больше не нужен,
  поэтому декларация выродилась в короткий маркер «рендери по стандартам».
</p>

<p class="info info--blue">
  XHTML-документ, отданный с MIME-типом <code>application/xhtml+xml</code>,
  всегда рендерится в standards mode — DOCTYPE-сниффинг применяется только к <code>text/html</code>.
</p>
