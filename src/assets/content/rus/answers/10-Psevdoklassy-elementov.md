<h3>Введение</h3>

<p>
  <span class="accent">Псевдокласс</span> — селектор через одно двоеточие (<code>:hover</code>), выбирающий
  <strong>уже существующий</strong> элемент по состоянию или позиции в дереве. В разметку он ничего не добавляет —
  этим отличается от псевдоэлемента (<code>::before</code>), который создаёт новый бокс.
</p>

<p class="info">
  <strong>Главная мысль:</strong> псевдокласс — условие на элемент, которое браузер проверяет сам и пересчитывает в
  реальном времени. Поэтому CSS реагирует на пользователя, валидность формы и структуру DOM без единой строки JS.
</p>

<hr />

<h3>Псевдоклассы состояния (интерактив)</h3>

<ul>
  <li><code>:hover</code> — курсор над элементом; <code>:active</code> — момент нажатия.</li>
  <li><code>:focus</code> — фокус получен любым способом (клик, Tab, скрипт).</li>
  <li><code>:focus-visible</code> — фокус, который браузер счёл нужным подсветить (обычно клавиатура).</li>
  <li><code>:focus-within</code> — на родителе, если фокус внутри него.</li>
</ul>

<p class="info info--orange">
  Не убирай <code>outline</code> у <code>:focus</code> — это ломает клавиатурную доступность. Приём: снять обводку
  у <code>:focus</code> и вернуть у <code>:focus-visible</code> — мышь её не увидит, клавиатура увидит.
</p>

<h3>Структурные псевдоклассы</h3>

<p>Выбирают элемент по позиции среди <strong>соседей</strong> (детей одного родителя):</p>

<ul>
  <li><code>:first-child</code> / <code>:last-child</code> / <code>:only-child</code>.</li>
  <li><code>:nth-child(An+B)</code> — по формуле: <code>2n</code>, <code>odd</code>, <code>3n+1</code>.</li>
  <li><code>:nth-of-type()</code>, <code>:first-of-type</code> — то же, но счёт только среди элементов того же тега.</li>
  <li><code>:empty</code> — без детей и текста.</li>
</ul>

<code class="code">
  li:nth-child(2n)      /* «зебра» */
  li:nth-child(-n + 3)  /* первые три */
  p:first-of-type       /* первый p, даже если перед ним h2 */
</code>

<h3>Функциональные псевдоклассы (Modern CSS)</h3>

<ul>
  <li><code>:is(a, b)</code> — группировка вместо длинных списков через запятую.</li>
  <li><code>:where(a, b)</code> — то же, но со <span class="accent">специфичностью 0</span>: для базовых стилей и библиотек.</li>
  <li><code>:not(sel)</code> — отрицание.</li>
  <li><code>:has(sel)</code> — «родительский селектор»: элемент, <strong>внутри</strong> которого есть нужный потомок.</li>
</ul>

<code class="code">
  /* было: 6 селекторов через запятую */
  :is(.content, .section) :is(h1, h2, h3) { color: red; }

  .card:has(img)                 /* карточка, в которой есть картинка */
  label:has(+ input:invalid)     /* подсветить label перед невалидным полем */
</code>

<h3>Псевдоклассы форм</h3>

<ul>
  <li><code>:checked</code> — отмеченный чекбокс, радио, <code>option</code>.</li>
  <li><code>:disabled</code> / <code>:enabled</code>, <code>:required</code> / <code>:optional</code>, <code>:read-only</code>.</li>
  <li><code>:valid</code> / <code>:invalid</code> — результат встроенной HTML-валидации.</li>
  <li><code>:user-valid</code> / <code>:user-invalid</code> — то же, но только <strong>после</strong> действий пользователя.</li>
  <li><code>:placeholder-shown</code> — поле пустое, виден плейсхолдер (основа «плавающих» лейблов).</li>
</ul>

<p class="info info--blue">
  Связка <code>:checked</code> + <code>~</code>/<code>+</code> даёт аккордеоны и табы без JS, а <code>:has()</code>
  снимает и требование, чтобы триггер стоял перед целью в разметке.
</p>

<p class="deep-dive">Углубленный конспект</p>

<h3>Специфичность функциональных псевдоклассов</h3>

<p>
  Это главная ловушка. <code>:is()</code>, <code>:not()</code> и <code>:has()</code> сами по себе весят 0, но принимают
  специфичность <strong>самого «тяжёлого» аргумента</strong> в списке. <code>:where()</code> всегда весит 0, что бы в него ни положили.
</p>

<code class="code">
  :is(#main, p) span { }    /* специфичность 1,0,1 — как у #main! */
  :where(#main, p) span { } /* специфичность 0,0,1 — как у одного span */
  li:not(.a, #b) { }        /* 1,0,1 — берётся #b */
</code>

<p class="info info--orange">
  Вывод: <code>:where()</code> — для стилей, которые должны легко перебиваться (reset, дефолты дизайн-системы).
  <code>:is()</code> — только когда осознанно нужен вес аргумента.
</p>

<h3>Forgiving selector list</h3>

<p>
  <code>:is()</code> и <code>:where()</code> используют «прощающий» список: если один селектор внутри невалиден или
  неизвестен браузеру, остальные продолжают работать. В обычном списке через запятую одна ошибка убивает всё правило —
  поэтому <code>:is()</code> удобен для прогрессивного использования новых селекторов.
</p>

<code class="code">
  /* правило целиком отброшено */
  .a, .b:unknown-thing { color: red; }

  /* .a по-прежнему работает */
  :is(.a, .b:unknown-thing) { color: red; }
</code>

<p>
  <code>:has()</code> и <code>:not()</code> — <strong>не</strong> forgiving: невалидный аргумент внутри них отбрасывает весь селектор.
</p>

<h3>:nth-child(An+B of S)</h3>

<p>
  Расширенный синтаксис: сначала отфильтровать соседей по селектору <code>S</code>, потом считать по формуле.
  Это не то же самое, что <code>:nth-child(2n).item</code> — там счёт идёт по всем детям, а фильтр применяется в конце.
</p>

<code class="code">
  li:nth-child(2n of .visible)  /* каждый второй среди видимых */
  li:nth-child(2n).visible      /* каждый второй из ВСЕХ, и он должен быть .visible */
</code>

<h3>Почему :has() так долго не появлялся</h3>

<p>
  Браузер матчит селекторы <span class="accent">справа налево</span> — от элемента-кандидата вверх по предкам.
  «Родительский» селектор ломает эту модель: чтобы решить судьбу родителя, нужно заглянуть в поддерево, а оно может
  измениться позже (стриминговый парсинг, динамический DOM). Инвалидация стилей при этом должна подниматься вверх,
  а не только вниз. Только в 2023 движки научились делать это достаточно дёшево, поэтому <code>:has()</code>
  безопасен на практике, но его не стоит вешать на очень широкие селекторы вроде <code>*:has(...)</code>.
</p>

<h3>:focus-visible: эвристика браузера</h3>

<p>
  Спецификация не фиксирует точный алгоритм. На практике движки подсвечивают фокус, если он получен с клавиатуры,
  если элемент — текстовое поле (там каретка нужна всегда), или если фокус выставлен скриптом, а предыдущее
  взаимодействие было клавиатурным. Клик мышью по кнопке даёт <code>:focus</code>, но не <code>:focus-visible</code>.
</p>

<h3>:valid / :invalid vs :user-valid / :user-invalid</h3>

<p>
  Пустое обязательное поле <code>:invalid</code> сразу при загрузке страницы — форма краснеет до того, как пользователь
  что-либо ввёл. <code>:user-invalid</code> решает это: браузер применяет его только после ввода или попытки отправки.
  Именно поэтому «правильная» валидация на чистом CSS сегодня пишется через <code>:user-invalid</code>,
  а не через <code>:invalid</code>.
</p>
