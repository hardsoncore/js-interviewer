<h3>Вступ</h3>

<p>
  <span class="accent">Псевдоклас</span> — селектор через одну двокрапку (<code>:hover</code>), що обирає
  <strong>уже наявний</strong> елемент за станом або позицією в дереві. У розмітку він нічого не додає —
  цим відрізняється від псевдоелемента (<code>::before</code>), який створює новий бокс.
</p>

<p class="info">
  <strong>Головна думка:</strong> псевдоклас — умова на елемент, яку браузер перевіряє сам і перераховує в
  реальному часі. Тому CSS реагує на користувача, валідність форми та структуру DOM без жодного рядка JS.
</p>

<hr />

<h3>Псевдокласи стану (інтерактив)</h3>

<ul>
  <li><code>:hover</code> — курсор над елементом; <code>:active</code> — момент натискання.</li>
  <li><code>:focus</code> — фокус отримано будь-яким способом (клік, Tab, скрипт).</li>
  <li><code>:focus-visible</code> — фокус, який браузер вирішив підсвітити (зазвичай клавіатура).</li>
  <li><code>:focus-within</code> — на батьківському елементі, якщо фокус усередині нього.</li>
</ul>

<p class="info info--orange">
  Не прибирай <code>outline</code> у <code>:focus</code> — це ламає клавіатурну доступність. Прийом: зняти обведення
  у <code>:focus</code> і повернути у <code>:focus-visible</code> — миша його не побачить, клавіатура побачить.
</p>

<h3>Структурні псевдокласи</h3>

<p>Обирають елемент за позицією серед <strong>сусідів</strong> (дітей одного батька):</p>

<ul>
  <li><code>:first-child</code> / <code>:last-child</code> / <code>:only-child</code>.</li>
  <li><code>:nth-child(An+B)</code> — за формулою: <code>2n</code>, <code>odd</code>, <code>3n+1</code>.</li>
  <li><code>:nth-of-type()</code>, <code>:first-of-type</code> — те саме, але лічба лише серед елементів того ж тегу.</li>
  <li><code>:empty</code> — без дітей і тексту.</li>
</ul>

<code class="code">
  li:nth-child(2n)      /* «зебра» */
  li:nth-child(-n + 3)  /* перші три */
  p:first-of-type       /* перший p, навіть якщо перед ним h2 */
</code>

<h3>Функціональні псевдокласи (Modern CSS)</h3>

<ul>
  <li><code>:is(a, b)</code> — групування замість довгих списків через кому.</li>
  <li><code>:where(a, b)</code> — те саме, але зі <span class="accent">специфічністю 0</span>: для базових стилів і бібліотек.</li>
  <li><code>:not(sel)</code> — заперечення.</li>
  <li><code>:has(sel)</code> — «батьківський селектор»: елемент, <strong>усередині</strong> якого є потрібний нащадок.</li>
</ul>

<code class="code">
  /* було: 6 селекторів через кому */
  :is(.content, .section) :is(h1, h2, h3) { color: red; }

  .card:has(img)                 /* картка, у якій є зображення */
  label:has(+ input:invalid)     /* підсвітити label перед невалідним полем */
</code>

<h3>Псевдокласи форм</h3>

<ul>
  <li><code>:checked</code> — позначений чекбокс, радіо, <code>option</code>.</li>
  <li><code>:disabled</code> / <code>:enabled</code>, <code>:required</code> / <code>:optional</code>, <code>:read-only</code>.</li>
  <li><code>:valid</code> / <code>:invalid</code> — результат вбудованої HTML-валідації.</li>
  <li><code>:user-valid</code> / <code>:user-invalid</code> — те саме, але лише <strong>після</strong> дій користувача.</li>
  <li><code>:placeholder-shown</code> — поле порожнє, видно плейсхолдер (основа «плаваючих» лейблів).</li>
</ul>

<p class="info info--blue">
  Зв'язка <code>:checked</code> + <code>~</code>/<code>+</code> дає акордеони й таби без JS, а <code>:has()</code>
  знімає й вимогу, щоб тригер стояв перед ціллю в розмітці.
</p>

<p class="deep-dive">Поглиблений конспект</p>

<h3>Специфічність функціональних псевдокласів</h3>

<p>
  Це головна пастка. <code>:is()</code>, <code>:not()</code> і <code>:has()</code> самі по собі важать 0, але приймають
  специфічність <strong>найважчого аргументу</strong> в списку. <code>:where()</code> завжди важить 0, хоч би що в нього поклали.
</p>

<code class="code">
  :is(#main, p) span { }    /* специфічність 1,0,1 — як у #main! */
  :where(#main, p) span { } /* специфічність 0,0,1 — як в одного span */
  li:not(.a, #b) { }        /* 1,0,1 — береться #b */
</code>

<p class="info info--orange">
  Висновок: <code>:where()</code> — для стилів, які мають легко перебиватися (reset, дефолти дизайн-системи).
  <code>:is()</code> — тільки коли свідомо потрібна вага аргументу.
</p>

<h3>Forgiving selector list</h3>

<p>
  <code>:is()</code> і <code>:where()</code> використовують «пробачливий» список: якщо один селектор усередині невалідний
  або невідомий браузеру, решта продовжує працювати. У звичайному списку через кому одна помилка вбиває все правило —
  тому <code>:is()</code> зручний для прогресивного використання нових селекторів.
</p>

<code class="code">
  /* правило відкинуто цілком */
  .a, .b:unknown-thing { color: red; }

  /* .a досі працює */
  :is(.a, .b:unknown-thing) { color: red; }
</code>

<p>
  <code>:has()</code> і <code>:not()</code> — <strong>не</strong> forgiving: невалідний аргумент усередині них відкидає весь селектор.
</p>

<h3>:nth-child(An+B of S)</h3>

<p>
  Розширений синтаксис: спершу відфільтрувати сусідів за селектором <code>S</code>, потім рахувати за формулою.
  Це не те саме, що <code>:nth-child(2n).item</code> — там лічба йде за всіма дітьми, а фільтр застосовується наприкінці.
</p>

<code class="code">
  li:nth-child(2n of .visible)  /* кожен другий серед видимих */
  li:nth-child(2n).visible      /* кожен другий з УСІХ, і він має бути .visible */
</code>

<h3>Чому :has() так довго не з'являвся</h3>

<p>
  Браузер матчить селектори <span class="accent">справа наліво</span> — від елемента-кандидата вгору по предках.
  «Батьківський» селектор ламає цю модель: щоб вирішити долю батька, треба зазирнути в піддерево, а воно може
  змінитися пізніше (стрімінговий парсинг, динамічний DOM). Інвалідація стилів при цьому має підніматися вгору,
  а не лише вниз. Лише у 2023 рушії навчилися робити це достатньо дешево, тому <code>:has()</code>
  безпечний на практиці, але не варто вішати його на дуже широкі селектори штибу <code>*:has(...)</code>.
</p>

<h3>:focus-visible: евристика браузера</h3>

<p>
  Специфікація не фіксує точний алгоритм. На практиці рушії підсвічують фокус, якщо його отримано з клавіатури,
  якщо елемент — текстове поле (там каретка потрібна завжди), або якщо фокус виставлено скриптом, а попередня
  взаємодія була клавіатурною. Клік мишею по кнопці дає <code>:focus</code>, але не <code>:focus-visible</code>.
</p>

<h3>:valid / :invalid vs :user-valid / :user-invalid</h3>

<p>
  Порожнє обов'язкове поле <code>:invalid</code> одразу під час завантаження сторінки — форма червоніє до того, як користувач
  щось увів. <code>:user-invalid</code> вирішує це: браузер застосовує його лише після введення або спроби відправлення.
  Саме тому «правильна» валідація на чистому CSS сьогодні пишеться через <code>:user-invalid</code>,
  а не через <code>:invalid</code>.
</p>
