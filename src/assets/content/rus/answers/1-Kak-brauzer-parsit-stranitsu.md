<h3>Critical Rendering Path</h3>
<p>Превращение HTML, CSS и JS в интерактивную страницу — это <span class="accent">Critical Rendering Path (критический путь рендеринга)</span>: цепочка шагов от байтов до пикселей.</p>

<p class="info"><strong>Скелет ответа:</strong> парсинг HTML → <code>DOM</code>, парсинг CSS → <code>CSSOM</code>, их объединение в <strong>Render Tree</strong>, затем <strong>Layout → Paint → Composite</strong>. HTML парсится инкрементально, но CSS и синхронный JS этот конвейер блокируют.</p>

<h3>Парсинг HTML → DOM, CSS → CSSOM</h3>
<p>Получив первые байты, HTML-парсер читает код сверху вниз, превращает теги в токены, а токены — в узлы, из которых строит <span class="accent">DOM</span> — дерево содержимого страницы. Парсинг идёт инкрементально, по мере скачивания.</p>

<p>Параллельно из CSS строится <span class="accent">CSSOM</span> — дерево стилей. CSS <strong>блокирует рендеринг</strong>: браузер не отрисует страницу, пока не построит полный CSSOM — иначе был бы FOUC.</p>

<h3>JavaScript блокирует парсинг</h3>
<p>По умолчанию <code>&lt;script&gt;</code> останавливает построение DOM: браузер скачивает и выполняет скрипт, и только потом продолжает парсинг HTML.</p>
<ul>
  <li><code>defer</code> — качается в фоне, выполняется после полного парсинга HTML, порядок подключения скриптов сохраняется.</li>
  <li><code>async</code> — качается в фоне и выполняется сразу по готовности, прерывая парсинг на время выполнения; порядок не гарантирован.</li>
</ul>

<h3>Render Tree → Layout → Paint → Composite</h3>
<p>DOM и CSSOM объединяются в <span class="accent">Render Tree</span> — в него попадают только видимые узлы (нет <code>&lt;head&gt;</code>, <code>&lt;script&gt;</code>, элементов с <code>display: none</code>).</p>
<ul>
  <li><strong>Layout (Reflow)</strong> — вычисление размеров и координат каждого элемента относительно вьюпорта.</li>
  <li><strong>Paint</strong> — заполнение пикселей: текст, цвета, границы, тени, фоны.</li>
  <li><strong>Composite</strong> — сборка слоёв в нужном порядке на GPU в итоговую картинку.</li>
</ul>

<h3>DOMContentLoaded vs load</h3>
<ul>
  <li><code>DOMContentLoaded</code> — HTML загружен и распарсен в DOM, без ожидания стилей, картинок и фреймов.</li>
  <li><code>load</code> — страница загружена полностью со всеми зависимыми ресурсами (картинки, стили, фреймы).</li>
</ul>

<p class="deep-dive">Углубленный конспект</p>

<h3>Preload Scanner</h3>
<p>Пока основной парсер стоит на синхронном скрипте, вспомогательный <span class="accent">Preload Scanner</span> «забегает» вперёд по HTML, находит внешние ресурсы (CSS, JS, картинки, шрифты) и начинает качать их заранее — так блокировка одним скриптом не останавливает всю загрузку.</p>

<h3>Почему CSS парсится не инкрементально</h3>
<p>В отличие от HTML, CSSOM нельзя строить по кусочкам: правило в конце файла может переопределить правило из начала (каскад). Поэтому браузер ждёт весь CSS, прежде чем считать CSSOM готовым.</p>
<p class="info info--orange">Синхронный скрипт после <code>&lt;link&gt;</code> ждёт построения CSSOM: JS может читать вычисленные стили, поэтому не выполнится, пока CSS не загружен — так CSS способен косвенно заблокировать и парсинг.</p>

<h3>Что попадает в Render Tree</h3>
<ul>
  <li><code>display: none</code> — узел исключается из дерева: он не рендерится вообще.</li>
  <li><code>visibility: hidden</code> и <code>opacity: 0</code> — остаются в дереве: элементы невидимы, но занимают место и влияют на геометрию.</li>
</ul>

<h3>Reflow и Repaint</h3>
<p><span class="accent">Reflow</span> — повторный Layout: пересчёт геометрии при изменении размеров или позиций (ресайз окна, вставка узлов, чтение <code>offsetHeight</code>). Дорогой, так как может каскадно затронуть и потомков, и предков.</p>
<p><span class="accent">Repaint</span> — перерисовка без изменения геометрии (смена цвета, фона). Дешевле reflow, но всё равно нагружает CPU.</p>
<p class="info info--blue">Анимация только через <code>transform</code> и <code>opacity</code> меняет лишь этап Composite, минуя Layout и Paint — поэтому идёт на GPU и держит 60 FPS (подробнее — в вопросе про производительность анимаций).</p>

<h3>Слои и композитинг</h3>
<p>Элементы с <code>transform</code>, <code>opacity</code>, <code>will-change</code> или <code>z-index</code> могут выноситься на отдельный композитный слой. Браузер растрирует слои независимо и склеивает их на GPU — это позволяет двигать слой, не перерисовывая остальную страницу.</p>
