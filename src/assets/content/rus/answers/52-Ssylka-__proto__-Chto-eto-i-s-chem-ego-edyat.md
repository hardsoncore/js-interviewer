<h3>Определение</h3>
<p><span class="accent">__proto__</span> — это исторический геттер/сеттер (свойство доступа), который позволяет прочитать или изменить скрытое внутреннее свойство объекта <code>[[Prototype]]</code>.</p>

<p>В JavaScript наследование реализовано через прототипы. <code>[[Prototype]]</code> — это физическая ссылка на другой объект (или <code>null</code>), от которого текущий объект наследует свойства и методы.</p>

<h3>Как работает цепочка (Prototype Chain)</h3>
<p>Когда интерпретатор пытается прочитать свойство или вызвать метод объекта, происходит следующее:</p>

<p>1. Идет поиск свойства в самом объекте.</p>

<p>2. Если свойство не найдено, поиск переходит к объекту, на который ссылается <code>__proto__</code>.</p>

<p>3. Этот процесс повторяется вверх по цепочке, пока свойство не будет найдено, либо пока <code>__proto__</code> не окажется равным <code>null</code> (обычно это происходит после <code>Object.prototype</code>).</p>

<h3>__proto__ vs prototype (Главная путаница)</h3>
<p>Это два совершенно разных понятия, которые работают в тандеме при создании объектов:</p>

<p><strong>prototype</strong> — это свойство функций-конструкторов (и классов). Оно существует до создания экземпляра и содержит объект, который будет назначен в качестве прототипа для всех будущих экземпляров, созданных через <code>new</code>.</p>

<p><strong>__proto__</strong> — это ссылка внутри <strong>уже созданного экземпляра</strong>, которая указывает на его прототип.</p>

<p class="info info--blue">
  Связь простая: instance.__proto__ === Constructor.prototype
</p>

<p>Например:</p>
<code class="code">
  function Person(name) {
    this.name = name;
  }

  Person.prototype.greet = function() {
    return `Hello, my name is ${this.name}`;
  };

  const alice = new Person('Alice');
  console.log(alice.greet()); // "Hello, my name is Alice"
  console.log(alice.__proto__ === Person.prototype); // true
</code>

<h3>Современный стандарт (Почему __proto__ это Legacy)</h3>

<p>Хотя <code>__proto__</code> и был стандартизирован в ES6 (исключительно ради обратной совместимости с браузерами), использовать его в рабочем коде — моветон.</p>

<p>Современные альтернативы:</p>

<p><strong>Чтение:</strong> Вместо <code>obj.__proto__</code> используй <code>Object.getPrototypeOf(obj)</code>.</p>

<p><strong>Запись:</strong> Вместо <code>obj.__proto__ = newProto</code> используй <code>Object.setPrototypeOf(obj, newProto)</code>.</p>

<p><strong>Создание с нуля:</strong> Лучший способ задать прототип — при создании объекта: <code>Object.create(newProto)</code>.</p>

<h3>Осторожно: производительность</h3>
<p>Изменение <code>[[Prototype]]</code> у уже существующего объекта (хоть через <code>__proto__</code>, хоть через <code>Object.setPrototypeOf</code>) — это катастрофически медленная операция. Современные JS-движки (например, V8) оптимизируют доступ к свойствам, создавая скрытые классы (hidden classes). Смена прототипа "на лету" разрушает эти оптимизации, заставляя движок деоптимизировать код.</p>
