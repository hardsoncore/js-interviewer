<h3>Observable — що це</h3>
<p><span class="accent">Observable</span> — це об'єкт-обгортка над функцією, яка з часом видає підписнику нуль, одне або скільки завгодно значень. Простіше кажучи — потік даних: кліки, відповіді сервера, значення поля форми. Сам по собі він нічого не робить: це лише опис того, що станеться під час підписки.</p>

<p class="info"><strong>Головна думка:</strong> Observable лінивий — усередині нього лежить функція, а <code>subscribe()</code> просто її викликає. Звідси виводиться все інше: без підписки роботи немає, кожна нова підписка запускає цю функцію заново, а щоб зупинити її — підписку потрібно закрити.</p>

<h3>Контракт: next, error, complete</h3>
<p>Observable спілкується з підписником трьома сигналами:</p>
<ul>
  <li><code>next(value)</code> — видати значення, викликів скільки завгодно;</li>
  <li><code>error(err)</code> — помилка, потік завершується, значень більше не буде;</li>
  <li><code>complete()</code> — потік нормально закінчився, значення не передається.</li>
</ul>
<p><code>error</code> і <code>complete</code> взаємовиключні та приходять щонайбільше один раз — це кінець життя підписки.</p>
<code class="code">
  const obs = new Observable((subscriber) =&gt; {
    subscriber.next(1);

    setTimeout(() =&gt; {
      subscriber.next(2);
      subscriber.complete(); // усе, що після — ігнорується
    }, 500);
  });

  const sub = obs.subscribe({
    next: (v) =&gt; console.log(v),
    error: (e) =&gt; console.log('Error:', e),
    complete: () =&gt; console.log('Done'),
  });
</code>
<p>Вручну через <code>new Observable</code> їх пишуть рідко — зазвичай беруть готові: <code>of</code>, <code>from</code>, <code>fromEvent</code>, запити <code>HttpClient</code>, <code>valueChanges</code> у форми.</p>

<h3>Чим відрізняється від Promise</h3>
<ul>
  <li><strong>Лінивість:</strong> проміс стартує одразу при створенні, Observable — лише при підписці.</li>
  <li><strong>Кількість значень:</strong> проміс віддає рівно одне і назавжди його фіксує, Observable — потік значень, доки не завершиться.</li>
  <li><strong>Скасування:</strong> підписку можна закрити і перервати роботу, проміс скасувати не можна.</li>
  <li><strong>Композиція:</strong> над потоком є <code>pipe()</code> з операторами — фільтрація, трансформація, об'єднання потоків.</li>
</ul>

<h3>Subscription і відписка</h3>
<p><code>subscribe()</code> повертає об'єкт <code>Subscription</code> — ручку від запущеного виконання з методом <code>unsubscribe()</code>. Він зупиняє роботу та звільняє ресурси.</p>
<p>Потоки, які самі доходять до <code>complete()</code> (запит <code>HttpClient</code>), закриваються самостійно. Нескінченні — <code>fromEvent</code>, <code>interval</code>, <code>valueChanges</code> — не завершаться ніколи, і відписатися маємо ми.</p>

<p class="info info--orange">Забута підписка — це витік пам'яті: її колбек тримає посилання на знищений компонент, і з кожним поверненням на сторінку додається ще один живий підписник. В Angular їх закривають через <code>async</code> pipe у шаблоні або оператор <code>takeUntilDestroyed()</code>.</p>

<p class="deep-dive">Поглиблений конспект</p>

<h3>Що таке Observable під капотом</h3>
<p>Клас <code>Observable</code> — це, по суті, об'єкт з одним полем: функцією, яку йому передали в конструктор. Метод <code>subscribe()</code> створює об'єкт <code>Subscriber</code> (безпечну обгортку над вашим спостерігачем) і викликає з ним цю функцію. Жодного реєстру підписників усередині немає — тому один Observable нічого не знає про інші свої підписки.</p>
<p>Функція підписки може повернути <strong>teardown</strong> — функцію очищення, яку RxJS викличе при <code>unsubscribe()</code>, <code>complete()</code> або <code>error()</code>. Саме так скасовуються реальні ресурси:</p>
<code class="code">
  const timer$ = new Observable((subscriber) =&gt; {
    const id = setInterval(() =&gt; subscriber.next(Date.now()), 1000);

    return () =&gt; clearInterval(id); // викличеться при відписці
  });
</code>
<p>Subscriber при цьому гарантує контракт: після <code>complete()</code> або <code>error()</code> він глушить усі подальші виклики <code>next()</code>, навіть якщо вихідна функція продовжує їх робити.</p>

<h3>Холодні та гарячі потоки, unicast</h3>
<p>Звичайний Observable <strong>холодний (cold)</strong> і <strong>unicast</strong>: функція-виробник живе всередині нього, тому кожна підписка запускає її з нуля й отримує власний набір значень. Два підписники на один <code>http.get()</code> — це два реальні HTTP-запити.</p>
<p><strong>Гарячий (hot)</strong> потік — той, де джерело живе ззовні та є спільним для всіх: <code>fromEvent(document, 'click')</code> або будь-який <code>Subject</code>. Підписники ділять одне виконання й отримують лише ті значення, що прийшли після їхньої підписки.</p>
<p>Перетворити холодний на гарячий можна операторами мультикасту: <code>share()</code> — одна спільна підписка, доки є хоча б один підписник; <code>shareReplay(1)</code> — те саме, але нові підписники одразу отримують останнє значення (частий спосіб закешувати відповідь сервера).</p>

<h3>Оператори та pipe</h3>
<p>Оператор — це чиста функція, яка приймає Observable і повертає <strong>новий</strong> Observable. Вихідний потік не мутується, тому ланцюжок <code>pipe(map(...), filter(...))</code> — це просто вкладені одна в одну обгортки.</p>
<p>Працює це так: підписка на підсумковий потік каскадом підписується вниз, аж до самого джерела, а значення йдуть назад угору через колбеки операторів. Тому <code>pipe()</code> сам собою теж нічого не виконує — без <code>subscribe()</code> ланцюжок мертвий.</p>

<p class="info info--blue">Часта помилка на код-рев'ю: викликали <code>http.get(...).pipe(tap(...))</code> і дивуються, що запит не пішов. Доки немає підписки — не буде й запиту.</p>

<h3>Синхронність і порядок виконання</h3>
<p>Observable не зобов'язаний бути асинхронним. <code>of(1, 2, 3).subscribe(...)</code> відпрацює повністю синхронно, до наступного рядка коду. У проміса так не вийде ніколи: <code>.then()</code> завжди відкладається в чергу мікротасків.</p>
<code class="code">
  console.log('start');
  of(1).subscribe((v) =&gt; console.log(v));
  Promise.resolve(2).then((v) =&gt; console.log(v));
  console.log('end');

  // start, 1, end, 2
</code>
<p>Момент виконання задає джерело або планувальник (Scheduler): <code>of</code> синхронний, <code>timer</code> та <code>interval</code> використовують таймери, оператор <code>observeOn(asyncScheduler)</code> примусово переводить потік в асинхронний режим.</p>

<h3>Помилки завершують потік остаточно</h3>
<p>Після <code>error</code> підписка мертва — «продовжити» її не можна, можна лише підписатися заново. Тому помилки обробляють операторами всередині <code>pipe()</code>: <code>catchError</code> підставляє запасний потік замість того, що впав, <code>retry(n)</code> перепідписується на джерело заново.</p>
<p class="info info--orange">Помилка в потоці, у якого немає обробника, у RxJS 7 не ковтається, а викидається назовні як необроблений виняток. Мовчазного падіння не буде, але й підписка не відновиться.</p>

<h3>Історична довідка</h3>
<p>Позиційну форму <code>subscribe(next, error, complete)</code> оголошено застарілою в RxJS 6.4, і у восьмій версії її буде видалено — передавайте об'єкт-спостерігач. Сама ідея прийшла з патерну Observer «банди чотирьох», а зараз Observable проходить стандартизацію: у браузерах на Chromium з'явився нативний DOM-метод <code>element.when()</code>, що віддає події вже у вигляді Observable.</p>
