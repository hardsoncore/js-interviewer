<h3>Введение</h3>
<p><span class="accent">DOM (Document Object Model)</span> — объектная модель документа: браузер парсит HTML и строит из него живое дерево узлов, а JavaScript через API этого дерева читает и меняет страницу. «Живое» — значит, изменил узел, и браузер перерисовал страницу. <span class="accent">DOM-события</span> — механизм реакции на действия пользователя и браузера: клик, ввод, скролл.</p>

<p class="info"><strong>Главная мысль:</strong> событие не срабатывает «в точке» — оно проходит путь по дереву: <strong>погружение → цель → всплытие</strong>. На всплытии построен главный практический паттерн — <strong>делегирование</strong>: один обработчик на родителе вместо сотен на потомках.</p>

<h3>Три фазы события (Event Flow)</h3>
<ul>
  <li><strong>Погружение (Capturing)</strong> — событие спускается от <code>window</code> и <code>document</code> вниз к цели.</li>
  <li><strong>Целевая фаза (Target)</strong> — событие достигло самого глубокого элемента, на котором произошло.</li>
  <li><strong>Всплытие (Bubbling)</strong> — событие поднимается обратно к корню, по пути вызывая обработчики родителей.</li>
</ul>
<p><code>addEventListener</code> по умолчанию слушает фазу всплытия. Чтобы перехватить событие на погружении, передают третий аргумент <code>{ capture: true }</code>.</p>

<h3>target vs currentTarget и остановка</h3>
<ul>
  <li><code>event.target</code> — элемент, на котором событие произошло (самый глубокий);</li>
  <li><code>event.currentTarget</code> — элемент, на котором висит текущий обработчик;</li>
  <li><code>event.stopPropagation()</code> — обрывает дальнейший путь события по дереву.</li>
</ul>

<h3>Делегирование событий (Event Delegation)</h3>
<p>Вместо обработчика на каждом элементе списка вешаем один на общего родителя: всплытие само принесёт событие наверх, а <code>event.target</code> подскажет, где именно кликнули.</p>
<code class="code">
  list.addEventListener('click', (event) => {
    const item = event.target.closest('li');
    if (!item) return; // клик мимо элементов списка

    selectItem(item);
  });
</code>
<p>Две выгоды: экономия памяти (один слушатель вместо тысяч) и работа с динамическим DOM — элементы, добавленные позже, не нужно подписывать заново: родитель и так поймает их события.</p>

<p class="info info--blue">В декларативных фреймворках вешать <code>(click)</code> / <code>@click</code> на каждый элемент списка — нормальный подход: код читаем, контекст передаётся напрямую. Делегирование включай осознанно — для огромных списков, сырого HTML и сторонних библиотек (разбор в Deep Dive).</p>

<p class="info info--orange">Не все события всплывают: <code>focus</code>, <code>blur</code>, <code>mouseenter</code>, <code>mouseleave</code>. Для делегирования фокуса есть всплывающие аналоги <code>focusin</code>/<code>focusout</code>. И не путай: <code>stopPropagation()</code> останавливает путь по дереву, а <code>preventDefault()</code> отменяет действие браузера по умолчанию.</p>

<h3>Зачем нужна фаза погружения</h3>
<p>На практике capturing используют редко: перехватить событие раньше всех остальных обработчиков (аналитика, временная блокировка интерфейса) или поймать на предке невсплывающее событие — фаза погружения проходит через предков всегда, даже если всплытия у события нет.</p>
<p>Сориентироваться, где сейчас событие, помогает <code>event.eventPhase</code> (1 — погружение, 2 — цель, 3 — всплытие). А <code>event.stopImmediatePropagation()</code> обрывает не только путь по дереву, но и остальные обработчики на текущем элементе.</p>

<h3>Опции addEventListener</h3>
<ul>
  <li><code>capture</code> — слушать на фазе погружения;</li>
  <li><code>once</code> — обработчик снимется сам после первого срабатывания;</li>
  <li><code>passive</code> — обещание не вызывать <code>preventDefault()</code>: браузер не ждёт выполнения JS и сразу прокручивает страницу. Критично для <code>touchstart</code> и <code>wheel</code>, поэтому в Chrome для них passive включён по умолчанию;</li>
  <li><code>signal</code> — привязка к <code>AbortController</code>: один вызов <code>controller.abort()</code> снимает целую группу обработчиков без хранения ссылок на функции.</li>
</ul>

<h3>Когда делегирование действительно необходимо</h3>
<p><strong>Большое количество элементов.</strong> Сотни строк таблицы, ячейки сложного календаря: тысячи слушателей — это лишняя память и время на подписку/отписку при каждом ререндере.</p>
<p><strong>Рендеринг сырого HTML.</strong> Если разметка приходит с бэкенда строкой и вставляется через <code>[innerHTML]</code> (Angular) или <code>v-html</code> (Vue), фреймворк не компилирует внутри неё свои директивы — <code>@click</code> там просто не заработает. Единственный способ ловить клики внутри такого блока — слушатель на обёртке и проверка <code>event.target</code>.</p>
<p><strong>Сторонние библиотеки.</strong> Плагины на Vanilla JS (графики D3.js, карты Leaflet) генерируют DOM-узлы в обход движка фреймворка. Делегирование на корневой обёртке — самый надёжный способ связать их события с методами компонента.</p>

<h3>Фреймворки и Shadow DOM</h3>
<p>React сам построен на делегировании: синтетические события слушаются не на элементах, а на корневом контейнере приложения (до React 17 — на <code>document</code>). Поэтому обработчик «на каждом элементе» в JSX почти ничего не стоит.</p>
<p>Shadow DOM добавляет ретаргетинг: когда событие всплывает из теневого дерева наружу, <code>event.target</code> подменяется на хост-элемент, чтобы не раскрывать внутренности компонента. Реальный путь события возвращает <code>event.composedPath()</code>, а пересекает ли оно границу тени — определяет флаг <code>composed</code>.</p>
