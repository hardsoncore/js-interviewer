<h3>Загальний принцип роботи (Web Storage API)</h3>

<p>І <strong>localStorage</strong>, і <strong>sessionStorage</strong> є частиною Web Storage API. У них ідентичний інтерфейс і однакова механіка роботи «під капотом»:</p>



<p>
  1. <strong>Формат даних:</strong> Зберігають дані виключно у форматі ключ-значення (key-value).
</p>
<p>
  2. <strong>Типізація:</strong> І ключі, і значення завжди конвертуються в рядки. Якщо потрібно зберегти об'єкт або масив, його необхідно серіалізувати (<code>JSON.stringify()</code>), а при читанні — розпарсити (<code>JSON.parse()</code>).
</p>
<p>
  3. <strong>Синхронність:</strong> Обидва API працюють синхронно. Це означає, що запис великого обсягу даних може заблокувати головний потік (Main Thread) браузера.
</p>
<p>
  4. <strong>Прив'язка до Origin:</strong> Дані жорстко прив'язані до джерела за формулою:
  <br>
  <code>Origin = протокол + домен + порт</code>
  <br>
  <br>
  Таким чином, сайт <code>https://example.com</code> не може прочитати сторадж <code>http://example.com</code> або <code>https://api.example.com</code>.
</p>
<p>
  5. <strong>Ліміти:</strong> У більшості сучасних браузерів квота становить близько 5 МБ на один Origin.
</p>

<h3>Основні відмінності та рекомендації щодо використання</h3>

<p>
  1. <strong>Час життя даних:</strong>
  <ul>
    <li><strong>localStorage:</strong> Дані зберігаються безстроково, поки користувач не видалить їх вручну або не очистить кеш браузера.</li>
    <li><strong>sessionStorage:</strong> Дані зберігаються тільки в межах однієї сесії. Вони видаляються при закритті вкладки або вікна браузера.</li>
  </ul>
</p>
<p>
  2. <strong>Доступність між вкладками:</strong>
  <ul>
    <li><strong>localStorage:</strong> Доступний у всіх вкладках і вікнах, відкритих на тому ж Origin. Зміни в localStorage в одній вкладці можуть бути виявлені в інших вкладках через подію <code>storage</code>.</li>
    <li><strong>sessionStorage:</strong> Доступний тільки в тій вкладці, де був створений. Інші вкладки не бачать дані sessionStorage.</li>
  </ul>
</p>
<p>
  3. <strong>Використання:</strong>
  <ul>
    <li><strong>localStorage:</strong> Ідеально підходить для зберігання даних, які мають зберігатися між сесіями, наприклад, налаштування користувача, теми оформлення, токени автентифікації (хоча для токенів краще використовувати HttpOnly cookies).</li>
    <li><strong>sessionStorage:</strong> Підходить для тимчасових даних, які потрібні тільки в межах однієї сесії, наприклад, дані форми, які не мають зберігатися після закриття вкладки.</li>
  </ul>
</p>

<h3>Шпаргалка по методах (API)</h3>
<p>Оскільки інтерфейс у них спільний (Storage), методи абсолютно однакові. Ось базовий CRUD:</p>

<code class="code">
  // 1. Запис (Create / Update)
  localStorage.setItem('theme', 'dark');

  // 2. Читання (Read)
  const theme = localStorage.getItem('theme'); // 'dark'

  // 3. Видалення одного елемента (Delete)
  localStorage.removeItem('theme');

  // 4. Повне очищення сховища
  sessionStorage.clear();
</code>

<h3>Важливі нюанси безпеки та архітектури</h3>

<p>
  <strong>Вразливість до XSS (Cross-Site Scripting):</strong><br>
  Будь-який JS-код, що виконується на сторінці, має доступ до Web Storage. Ніколи не зберігай там конфіденційні дані: паролі, номери кредитних карток або персональні дані.
  (Суперечки щодо зберігання JWT-токенів у localStorage тривають постійно. Це зручно, але менш безпечно, ніж зберігання в httpOnly куках, оскільки токен можуть викрасти через XSS вразливість).
</p>
<p>
  <strong>Синхронне блокування:</strong><br>
  Не пиши і не читай величезні масиви даних (мегабайти) зі сховища в циклі. Це заморозить UI (особливо критично для рендерингу у Vue/Angular). Якщо даних багато — краще подивитися в бік IndexedDB.
</p>
